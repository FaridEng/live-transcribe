- **Packaging (D19), raised by the user on 2026-09-20:** there is no installer and none is planned - the PRD lists "installer polish, code signing, auto-update" as an explicit non-goal, because the audience is one machine. The app therefore runs from `src/LiveTranscribe.App/bin/Debug/net10.0-windows/`, and the sign-in entry points there, so it breaks if that folder is cleaned or moved. Two ways out, if the user wants one: (a) a publish script that produces a self-contained single exe in a stable folder such as `%LOCALAPPDATA%\Programs\LiveTranscribe` - about an hour, no new dependency, and it fixes the stale-path problem; (b) a real per-user installer (Inno Setup or WiX) with a Start-menu shortcut and an uninstall entry - a day, and unsigned it still shows a SmartScreen warning. Auto-update stays out either way.
- **Giving it to someone else, asked on 2026-09-20:** a warning-free install is reachable without paying for a certificate, but only if the files never carry a Mark of the Web. Handed over on a USB stick or a local share, a per-user Inno Setup installer (`PrivilegesRequired=lowest`, into `%LOCALAPPDATA%\Programs`) over a self-contained publish shows nothing at all: no SmartScreen, no UAC (the manifest is `asInvoker`), no .NET prompt, no firewall prompt (the app only makes outbound connections). Sent as a download or an email attachment, the same file gets a Mark of the Web and SmartScreen shows "Windows protected your PC" once per machine. Removing that needs code signing: Azure Trusted Signing (~$10/month, but individuals need a verifiable three-year history and it is region-limited) or an OV certificate on a hardware token (~$300-400/year) - and neither kills the warning immediately, because SmartScreen reputation accrues with downloads. Only an EV certificate is instant, and it normally needs a registered company. A separate risk, whatever the transfer: the global keyboard hook in `HotkeyHook.cs` can trip antivirus heuristics on an unsigned build. Not decided.
- **Microsoft Store, asked on 2026-09-20:** it is the only route to a warning-free *download* without buying a certificate, because Microsoft signs the MSIX itself; the developer account is a one-time ~$19, and updates and clean uninstall come free. The cost moves from money to work and policy. Code changes needed: `StartupRegistration` must use the `windows.startupTask` manifest extension instead of the HKCU Run key, since MSIX virtualizes that write away, and `AppPaths` (`%APPDATA%\LiveTranscribe`) has to be re-tested under the package. `runFullTrust` is a restricted capability, normally granted for a desktop app, and the low-level keyboard hook plus the UIA reads of other apps' windows are the parts most likely to draw a reviewer's question. Submission also needs a privacy policy URL (the app sends audio to Google), an age rating, and working test credentials, because a reviewer cannot dictate without a Gemini API key. Estimate 2-3 days plus review turnaround, against about a day for the Inno Setup route. Listing a plain EXE/MSI in the Store instead of an MSIX does not avoid the certificate: Microsoft requires that installer to be signed. Not decided.
- **Copying the build folder to someone else, asked on 2026-09-20:** it carries no credentials. `bin\Debug\net10.0-windows` holds only binaries; the key lives in `%APPDATA%\LiveTranscribe\secrets.bin`, and DPAPI's current-user scope (no `CRYPTPROTECT_LOCAL_MACHINE` flag) makes that file undecryptable under any other account even if it were sent too, which is FR-11.3 working as intended. The recipient enters their own key, which also keeps the free-tier quota separate (D20). The real snag is that the build is framework-dependent: `LiveTranscribe.runtimeconfig.json` asks for `Microsoft.WindowsDesktop.App 10.0.0`, so a plain copy dies with a runtime dialog unless they install the .NET 10 Desktop Runtime. A self-contained publish removes that, and is the first half of the Inno Setup option above.
- **Another provider than Gemini (D21):** still Gemini only. The engine interface, the profile list and the model directory are provider-neutral, so another provider is a new engine class plus a row in `EngineType`, not a rewrite. Say so if D21 should change.
